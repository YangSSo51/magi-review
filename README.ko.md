# 마기식 검토 — MAGI Review

**문제의 근거와 반례를 확인하고, 하나의 실행 계획으로 정리합니다.**

[설치 안내](INSTALL.md) · [사용 예시](docs/EXAMPLE.md) · [연구 자료](docs/RESEARCH.md) · [MIT 라이선스](LICENSE)

Codex와 Claude Code에서 **명시적으로 호출할 때만** 사용하는 검토 스킬입니다. 기존의 **3관점 독립 평가**와 새 **주 계획·반증 검토** 중 선택하고, 고정된 코드 버전·판단 기준을 근거로 하나의 Plan과 실행용 Goal을 만듭니다.

## 검토 방식 선택

| 방식 | 구성 | 용도 |
| --- | --- | --- |
| 3관점 평가 — 기본 추천 | 같은 선택 모델의 평가자 3개 | 목적·효용, 정확성·안전성, 단순성·운영성을 독립 검토 |
| 주 계획·반증 검토 | 주 계획 모델 1개 + 다른 검토 모델 1개 | 계획의 틀린 주장·누락된 실패 경로·불필요한 수정을 근거로 확인 |

모드와 역할별 모델을 먼저 선택합니다. 주 계획·반증 방식에서는 같은 코드 스냅샷(커밋뿐 아니라 관련 미커밋·미추적 내용 포함), 기준 ID·우선순위·완료 증거를 고정합니다. 검토자는 고정된 초안을 읽고 반증하며, 조정자는 지적을 **확인 / 조건부 / 기각 / 자료 부족**으로 판정해 계획 변경 이유를 남깁니다. 두 계획을 단순히 합치지 않습니다.

```text
/magi-review 주 계획·반증 검토 방식으로 진행해줘. 주 계획과 검토 모델을
따로 선택하고, 코드 버전과 추천 판단 기준을 고정한 뒤 지적을 판정해서
하나의 최종 Plan과 Goal로 정리해줘.
```

Codex에서는 `$magi-review`를 사용합니다. Claude·Codex 모델을 한 호스트에서 함께 실행할 수 없다면 수동 인계 또는 사용자가 실행·소스 접근을 승인한 두 번째 호스트의 도구·CLI를 사용할 수 있습니다. 두 역할은 동일한 문제·코드 스냅샷·판단 기준을 받고, 반증 역할만 고정된 주 계획 초안을 추가로 받습니다. 자동 제공업체 라우팅이나 계정 연결을 대신하지 않으며, 실제 두 번째 실행 없이 교차 모델 검토 완료로 표시하지 않습니다. 비공개 검토 산출물은 공개 스킬 저장소 밖에 보관하며, 스킬 개선 게시 권한을 검토 프로젝트 공개 권한으로 해석하지 않습니다. [상세 절차](skills/magi-review/references/plan-challenge.md)

## 3관점 평가의 사용 흐름

1. 현재 도구에서 서브 에이전트에 사용할 수 있는 모델 목록과 `Default`를 제시합니다. Default는 이 검토에서 현재 세션 모델을 상속한다는 뜻입니다. 계정 기본값을 변경하지 않습니다.
2. 사용자가 문제 상황이나 목적을 제시합니다. 필요한 경우 질문으로 구체화합니다.
3. AI가 판단 기준 3–6개, 추천 우선순위, 확인 가능한 성공 증거를 **먼저 리스트업**합니다. 사용자가 수락·수정한 뒤 평가합니다. 처음부터 추천 기준 사용을 명시적으로 맡길 수도 있습니다.
4. 같은 모델의 서브 에이전트 세 개가 서로의 첫 답변을 보지 않고 평가합니다.
5. 중요한 쟁점만 최대 한 차례 교차 검토하고 근거로 확인합니다.
6. Plan과 실행용 Goal을 제시합니다. 네이티브 Goal 등록과 구현 시작은 사용자의 요청 범위에 따릅니다.

모델은 대개 로컬에 설치된 프로그램이 아니라 계정·호스트에서 접근 가능한 원격 모델입니다. 스킬은 모델 설치나 타 제공업체 연결을 대신하지 않습니다. 목록을 확인할 수 없으면 한계를 알리고 선택을 요청합니다.

## 설치와 호출

설치 스크립트는 Python 3.10+ 표준 라이브러리만 사용하며 기존 경로를 덮어쓰지 않습니다. 아래 경로는 예시입니다. 대상 프로젝트에서 실행하거나 실제 절대 경로로 바꾸세요.

```sh
python /path/to/magi-review/scripts/install.py --host codex --destination .agents/skills/magi-review
python /path/to/magi-review/scripts/install.py --host claude --destination .claude/skills/magi-review
```

개인용 경로 및 Python 없이 복사하는 방법은 [설치 안내](INSTALL.md)에 있습니다. Claude용으로 수동 복사할 때는 SKILL.md frontmatter에 `disable-model-invocation: true`를 추가해야 합니다. 설치 스크립트는 이를 자동 적용합니다.

- Codex: `$magi-review 이 문제를 검토해줘. 모델 선택과 목적 구체화, 판단 기준 추천부터 시작해줘.`
- Claude Code: `/magi-review 이 문제를 검토해줘. 판단 기준을 추천하고 확인받은 후 진행해줘.`

핵심 지침은 영어로 작성했고 응답은 사용자 언어를 따릅니다. 일반 Claude 채팅처럼 서브 에이전트 도구가 없는 환경의 실제 3개 에이전트 실행은 지원하지 않습니다. 주 계획·반증 방식의 수동 인계도 실제 역할 실행과 동일 입력 확인이 필요합니다.

## 연구 근거와 검증 상태

[연구 노트](docs/RESEARCH.md)는 성공 사례와 부정적 결과를 함께 다룹니다. 특히 동일 모델의 세 역할을 사용한 MABPD, 역할 편향을 확인한 Beyond Consensus, 같은 예산의 독립 응답과 비교한 Beyond Symmetric Agents가 설계에 관련됩니다. 이 스킬 자체가 최신 고성능 모델의 개발 작업에서 성능을 높인다는 실험 결과는 아직 없습니다.

Codex의 모델·판단 기준 선택, 격리된 세 평가자 실행, 근거 확인, Plan과 네이티브 Goal 등록을 [검증했습니다](docs/CODEX-VALIDATION.md). Codex 선택기 자동 발견은 미검증입니다. [Claude Code 검증](docs/CLAUDE-VALIDATION.md)에서는 네이티브 슬래시 호출, 서로 다른 컨텍스트의 `opus/high` 세 평가자, 조정자의 근거 확인, Plan과 미등록 텍스트 Goal을 확인했습니다. 세 평가자의 응답은 `claude-opus-5-5`를 표시했으며 이는 호스트의 모델 식별 정보로, 백엔드의 독립 인증은 아닙니다. Default 상속·다른 모델·원래 평가자를 재개하는 교차 검토는 미검증이며, 이 실행들은 성능 향상이나 일반적 신뢰성을 입증하지 않습니다.

MIT 라이선스로 배포합니다. [GitHub 저장소](https://github.com/YangSSo51/magi-review)에서 설치할 수 있습니다. [게시 및 검증 확인 사항](docs/RELEASE.md)

기존 실환경 실행 기록은 **3관점 방식**에 관한 것입니다. 새 주 계획·반증 모드와 교차 호스트 인계는 아직 실환경 종단 간 검증을 수행하지 않았습니다.
